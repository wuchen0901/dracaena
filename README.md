## 小游戏（`mini/`）

2026-11-17 主游戏的画面先放着，另做了两个画面简单的解谜小游戏试试手感，和 `Last/` 互不相干。都是单个 HTML 页面，不用联网、不用构建，直接用浏览器打开就能玩；电脑上用键盘，手机上点屏幕。2026-11-18 又加了一屏点击解谜的试验（门厅）。

- `mini/index.html`：入口页，每个游戏一张卡片。
- `mini/prism.html` · **棱光**：光束反射。点镜子，镜子转 45°；点棱镜，棱镜翻面。把光引到所有晶体上就过关。白光过棱镜分成红、绿、蓝，颜色可以混（红 + 绿 = 黄，三色合起来又是白），晶体要的颜色多一种少一种都不亮。8 关，有撤销、重来、两级提示（第一下圈出该转的那一个，第二下画出该转到的角度）。手机竖着拿时关卡自动转 90°。
- `mini/lamplight.html` · **灯下**：Creaks 那一类的玩法（只借“灯光把怪物变成家具”这个机制，名字、角色、关卡都是自己的）。侧面剖开的一栋房子，一步一回合：你走一步，影子走一步。影子被灯照到变成家具、不动，回到暗处又醒过来；家具挡路但能踩上去。三种影子：扑影（同一层看见你就扑过来，照到变衣柜）、学影（学你左右走，照到变椅子）、游影（来回走，照到变座钟，规则写好了、关卡里还没用）。还有拉杆、踏板和铁门、梯子。5 关，有撤销、重来，被抓住了可以退一步。
- 灯下的画面 2026-11-17 重画了一遍，先把第一关做成标杆画面（规则那一段一个字没动）。画法只有一句话：**暗处只有冷色的剪影，灯照到的地方才有颜色和细节**。调子是“安静的怕”：影子只有黑和一双眼睛，家具就是家具、没有脸，什么都不描边。
  - 一栋夜里的房子剖开来看：夜空、月亮、几缕云、房子后面一棵枯树，屋顶、烟囱，房子坐在地面上（原来是一块砖墙浮在全黑里，房子只占屏幕高度的 38%）。格子放大了，第一关在 1280×800 上从 76 像素一格变成 96。
  - 屋子画了两层：没照到的一层是冷的深蓝，只看得出墙纸、护墙板、画框的深浅；照到的一层是暖的，有颜色（砖红墙纸和上面的小菱形、绿护墙板、木地板、画里画的东西、地毯）。每盏灯的光是一个“帐篷”形 —— 灯罩口窄，往下很快张开，到地面正好是规则里的五格 —— 照到的地方换成暖的那一层，再加一层光晕、光里的灰尘、两只绕着灯泡飞的蛾子。开灯闪一下才亮稳。
  - 暖光才算数：光画到哪儿，规则里就照到哪儿。墙上的光是软边，地板不带软边 —— 照到哪一格就亮到那一格的边，看地板就知道哪几格算数。月光和出口是冷光，只是好看，不算“照到”。
  - 出口从发暖光的门改成后墙上一道拱门，门外是月光。拉杆挪到头顶上方（原来和人的头叠在一起），电线从拉杆沿墙上去、贴着天花板走到它管的灯，不看颜色也知道哪根管哪盏；铁门开的时候沉进地板；地板上的铁盖子画成盖在洞口上的一块格栅。
  - 主角换成主游戏那个孩子的样子（乱头发、米白卫衣、长裤、靴子，原来是黄雨衣）：暗处是偏冷的浅色剪影，走进灯下才有颜色；爬梯子时背对着我们。影子是全画面最黑的，只有一圈冷色的边和眼睛；扑影改成一摊矮矮的黑、顶上几缕往上飘，看见你时眼睛和边变红（原来就有）。

    - `mini/tools/looks.html`：只是画面，不能玩。地图、陈设、每样东西的位置和大小都是从 `lamplight.html` 抄的，所以这里画成什么样，搬回游戏里就是什么样。不带参数打开是两版各两张（灯关 / 灯开）；`?one=a` 或 `?one=b` 只画一张 1280×800，再加 `lit=1` 开灯、`px` `py` 摆主角、`mx` 摆影子、`dpr=2` 画两倍大。预览用 `mini-games`（<http://127.0.0.1:8790/tools/looks.html>），直接双击打开也行。

    - 原来那句话没变：暗的一层和亮的一层是同一张画（线的走法一样），暗的那层冷、只有轮廓，亮的那层暖、有细节。地板的规矩也没变：照到哪一格就亮到那一格的边。
    - 灯光改成没有形状（2026-11-17）。主人看了第一版说“灯光的形状很奇怪”，又说清楚了：奇怪的是**灯光居然是帐篷的形状** —— 光不该有一个轮廓。游戏里现在的光是一个“帐篷”（灯罩口窄，在灯自己那一行就张满五格，再直着落到地板），为的是让规则里照到的格子全在光里；中间试过改成一个锥，那还是一个帐篷，已经拿掉了。
      - 现在这样画：灯泡周围最亮，往外慢慢暗下去，到三格开外就没了（`lightAt`）；灯罩挡掉一部分往上的光。由亮到暗不是一道光滑的渐变，也没有一条边：按一张“排线深浅图”（`toneTex`）一层层加密 —— 先出现一个方向的排线，再加交叉的，排线之间也一起慢慢暗下去，最后整片黑。
      - 灯下的人和家具也跟着暗：离灯越远越暗、越偏冷（`inLight`），所以站在最外面那一格的衣柜比墙中间暗。
      - 地板还是硬边：照到哪一格就亮到那一格的边，看地板就知道哪几格算数；只是离灯远的格子暗一些，不再是一整条一样亮的带子。
      - 规则不用改：这个页面又回到和游戏一样的规则（左右各两格、往下三格）。在五关的每一盏灯上比过：“离灯泡不到 2.4 格”挑出来的格子和游戏规则一模一样（2.3 到 3 格之间取哪个半径都一样），所以光画到哪儿、规则就算到哪儿。这只对两格高的房间成立；以后有三格高的房间，两种算法在最下面那一行会不一样，到时候再定按哪个。
      - 游戏里的光还是帐篷形，没动。前后对比在 `generated_images/lamplight-looks-02-light.jpg`：原来的帐篷、中间那一版的锥、现在的 A 和 B。

- `mini/hall.html` · **门厅**（2026-11-18）：试一屏 Machinarium 那一类的点击解谜，看这种玩法做起来、看起来怎么样。只有一个房间、一个谜题，画法照《灯下》：暗处只有冷色的剪影，灯照到的地方才有颜色，主角是同一个孩子，色表是同一套。
  - 玩法：点哪儿走到哪儿；点东西，孩子走过去伸手（开抽屉、开钟门、捡东西、拧灯泡、摇绞盘、开门）。捡到的东西进下面的物品栏，点一下拿在手里，再点要用的地方。没有字：点错了，用动作和孩子头上气泡里的小图告诉你差什么（摇头；退两步、发抖；气泡里画一个灯泡、摇把、钥匙，或者一盏灯带一个往下的箭头）。右上角的 ? 是提示，照最短的解法在气泡里画出下一步该点什么。
  - 谜题：门口站着一个影子，孩子走到跟前就不敢再走（退两步、发抖，影子的眼睛和边变红）。灯照到它，它就是一个衣帽架，钥匙挂在上面 —— 和《灯下》里“影子被灯照到变成家具”是一回事。抽屉里有灯泡，拧到吊灯上灯就亮了，可是灯挂得低，只照得到屋子中间；座钟肚子里挂着摇把，装到墙上的绞盘上把灯摇上去，光张开，照到门口。最少点 8 下。光照到它多少，就透出多少大衣（亮的一层里永远画衣帽架，暗的一层里画影子，光照到哪儿就露出哪一层）；等光照到它的头，它才整个变成衣帽架，孩子才敢过去。
  - 画面：固定 1600×900 的一屏，按窗口等比缩放。屋子画两张（暗的、亮的），会动的东西（抽屉、钟门和钟摆、绞盘、门、影子和衣帽架、孩子）每一帧两层各画一遍，再按光把亮的那一层抠出来盖上去。光没有形状、没有边（照上面《灯下》画法试验里主人说的：灯光不该是帐篷的形状）：灯泡附近最亮，往外慢慢暗下去，灯罩挡掉大部分往上的光；灯挂得越高照得越开（`LIGHT_LOW`、`LIGHT_HIGH`）。所以灯在低处时只照亮孩子身边一小片，影子靠灯的那半边已经隐约透出大衣，头还在暗处；灯升上去，屋子中间一大片暖光，窗边、钟和门口还是冷的。灯被碰到会晃，光跟着晃。月光从左边的高窗斜着落在地板上，孩子站在里面亮一些，只是好看，不算“照到”。暗处能开、能拧的铜件（抽屉把手、钟门的扣、绞盘、门把手）隔一会儿闪一下。
  - 孩子的动作是算出来的，不是一帧一帧画的：腿和伸出去的手用两节的反解，步子按速度从走过渡到小跑，脚在地上不打滑；还有伸手、拧、摇、踮脚、害怕、摇头、走出门。

新故事（`design/environmental-escape-story.md`）2026-11-15 做了一版灰模，原来是七章加结尾；同一天把第一章“焚化炉”删掉了；2026-11-16 在大门后面加了一章“雾”。现在七章加结尾，是游戏的第 1–8 章，直接打开页面就从“分拣”开始：

跳跃的手感（2026-11-16 改过，`src/50-player.js` 的 `stepPlayer`）：每一跳都一样高，点一下空格和按住不放没有区别（以前松开空格会把上升掐断，短按只有半人高）；腾空以后不按方向键，横着的速度原样留着，顺着起跳时的抛物线落下去（以前一松手就在半空刹住、直直掉下来），按着方向键还是能在空中带一点方向、往回收。最远能跳多远、最高能跳多高都没变。

跳跃的动作（2026-11-16 改过，`src/42-character-anim.js` 的 `JUMP`）：腾空不再是一个固定的姿势，按竖直速度从蹬地、提膝、最高点收腿、伸腿找地一路过渡到着地前；手臂像弹簧一样跟着，落地以后往下一荡再收回来。只改了动作，跳多高、多远、多久不变。`Last/tools/jump-sheet.html` 在游戏里把它拍成连续帧，`?layout=check` 报出高度、距离和手脚每帧挪了多少。

起跳前蹲一下蓄力（2026-11-16 加的，`src/50-player.js` 的 `JUMP_PREP`，动作在 `42-character-anim.js` 的 `JUMP.prep`）：按下跳以后人不是立刻离地，先屈膝往下一沉、上身前倾、手臂往后摆，站着 0.11 秒、跑着 0.06 秒以后才蹬起来（跑着跳比以前多冲出去 0.2 米才离地）。蹲的这一小会儿照样能走能跑；已经走出边缘才按跳的来不及蹲，直接跳；蹲的时候走出了边缘，到时候照样跳起来。离地以后跳多高、多远、多久都不变。

松开方向键（2026-11-16 改过，`src/50-player.js` 的 `STOP`）：在地上松手以后带着惯性刹一小段再停住 —— 跑着松手往前带不到半米、0.43 秒停住，走着松手带十几厘米（以前 0.07 秒就掉了六成多的速度，跑着也只带二十厘米，像被钉在地上）；刹车时重心压低一点、手臂放低。过场里主角自己走的那几段照旧，站的位置不变。`jump-sheet.html?rows=stop,wstop` 拍的是这一段。

按反方向掉头（2026-11-16 改过，`src/50-player.js` 的 `SKID`）：在地上跑着、走着的时候按另一边，先刹住再往回走，还冲得快的时候人朝着原来的方向刹车，慢下来才转过身 —— 跑着掉头往前多冲 0.3 米、0.27 秒刹住、0.53 秒往回跑到九成快（以前 0.08 秒速度就反过来了，人像被弹回去的）；走着掉头多冲 8 厘米。转身的动作（`42-character-anim.js` 的 `TURN.w`）也从“头一帧最快”改成起得慢、中间快、收得慢。腾空时的转向和过场里的走动照旧。`jump-sheet.html?rows=turn,wturn` 拍的是这一段。

起步（2026-11-16 改过，`src/50-player.js` 的 `START`）：在地上按下方向键，先匀着加速、快到全速了再缓下来 —— 0.2 秒到全速的一半、0.41 秒到九成，走和跑一样久（以前头一帧加速度最大，0.08 秒就到一半，人是窜出去的）；头 0.3 秒比以前少走 0.28 米。掉头以后往回跑也是这样起步，所以跑着掉头到往回九成快一共 0.68 秒。腾空时带方向、过场里的走动照旧。`jump-sheet.html?rows=go,wgo` 拍的是这一段。

攀爬的动作（2026-11-16 改过，`src/42-character-anim.js` 的 `MANTLE`，位置在 `src/50-player.js` 的攀爬那一段）：以前是摆好一个收着腿的姿势，整个人顺着侧面匀速滑上去、再平着滑到顶上 —— 跳早了、往下掉的时候腰撞在箱子角上（边缘只到腰那么高）最明显，人像被平着提上去的。现在是真的撑上去：两只手按在顶面上不动，刚抓住的那一下身子还往下沉一点（掉得越快沉得越多，最多 7 厘米），上身伏到顶面上，手臂把胯撑过边缘；一条腿先绕过边角踩到顶上、踩住就不动，身子从它上面翻过去，另一条腿顺着侧面垂着、最后才提上来迈到前面，一边站直。边缘高（吊着）的时候前面多一段往上拉，后面一样；从水里爬上岸、从绳子翻上高台用的也是这一段。什么时候能攀、花多久、最后站在哪都没变（腰高的箱角还是 0.62 秒）。对比图在 `generated_images/jump/mantle-01-before.png` / `mantle-01-after.png`（每格隔 1/30 秒）。在无头 Chrome 里拍过腰高、膝盖高、1.3 米高的边缘，朝左、搭出来的小孩、水里上岸各一次；从绳子翻上高台没拍，没有亲手玩过。

## 动捕对比（试验，2026-11-16）

想看看把主角的走和跑换成动作捕捉会是什么样：`Last/tools/mocap-compare.html`（通过本地服务器打开，比如 <http://127.0.0.1:8765/tools/mocap-compare.html>）左右并排放两个游戏，左边是现在程序化的走和跑，右边是同一个主角、地上走和跑换成 Mixamo 的动捕；两边按键、时间完全一样。能选跑、走、跑停跑、走跑交替、跑跳跑，能慢放到 1/10、暂停、单步。

- 游戏本身默认不变：地址后面加 `?mocap=1` 才打开（`src/42-mocap.js`，在 `42-character-anim.js` 摆完姿势以后混进去）。只管在地上走和跑；站着、起跳、腾空、落地、刹车、攀爬、游泳、推箱子、剧情动作的时候动捕淡出，照旧用程序化的。

- 重定向：Xbot 和主角的骨架长短、绑定姿势不一样，先把主角每节骨头在绑定姿势里转到和 Xbot 同一个方向，以后每一帧 Xbot 那一节比绑定姿势多转多少，主角也多转多少；胯的上下颠按两个人胯的高度之比缩放。主角模型的三节脊椎是倒着编号的（Hips → Spine02 → Spine01 → Spine → neck，和 Mixamo 相反），对应表里换过来了。
- 步子按走过的距离推进，脚不打滑。Xbot 的 run 换算到主角身上原本约 2 米/秒，游戏里跑是 3.3 米/秒，所以右边的跑比原动作快 1.6 倍左右播放，步频偏急；走（1.25 米/秒）和原速差不多。没有脚的 IK，坡上脚会悬空或插进地里。
- 查过的：无头 Chromium 里拍过平地上跑、走、往左跑各一个循环，和程序化的并排比过；跑跳跑那一段看过动捕淡出、淡入没有跳变（落地后约 0.2 秒混回来）；对比页能载入、切换场景。没有亲手玩，没在手机上看，无头浏览器里页面跑得很慢（软件渲染），真机上的流畅度没看。

## 模型对比（试验，2026-11-16）

## 第 37 章 · 草地

`Last/sidescroller/src/69-m01-meadow.js`，2026-11-17 加的，`?ch=37`（或者按 Esc，右边一列最下面“出了工厂”）。第 36 章“铃”演完，结尾画面上按 → 接着往前走：盖着的白慢慢退掉，人站在门外白茫茫的一片里；往右走，白一点点退成灰、再退成夜 —— 门外那一片白原来是雾。

- 夜里的一片荒地，月亮在左上方。草长成一窝一窝的（一两米大小，常常三五窝挨在一起），草窝中间是光着的土地：深深浅浅的土、干裂的细纹、碎石子和大大小小的石头。脚步声踩进草窝是草，出来是土。
- 雾只伏在草窝上，很浅、很淡，没有草的地方没有雾。草的底下一截不画：从根往上大约 0.12–0.36 米渐渐显出来（每一根错开一点），只画伸出来的上半截和被月光照着的草尖（草尖自己带一点亮）。这样薄薄一层雾就像把草根盖住了，看上去像是雾底下一整窝草，其实就那么几根长草（一根到四五根叶子一丛，也有带穗的草茎）；矮草反正看不见，不摆了。窝中间的草高，边上的矮。
- 没有谜题，是一段走过去的路：一道干砌矮石墙（0.8 米）要跳过去；洼地里草窝多一些、雾稍深一点，有一棵枯树；路后面一道旧栅栏；坡上一排木桩斜着往远处去；坡顶是整条路的尽头（空气墙，原来在第 36 章右墙那里）。
- 第一版（同一天）是满地铺雾、草零零星星撒满一地；第二版改成草窝 + 光地，但雾要把草根盖严实，得又厚又亮。两版在夜里看着都像雪。第三版（现在）让草自己没了底，雾就能很薄很淡。
- 雾的做法：贴着地面一层层叠起来的半透明薄片（电脑上 10 层，触屏 6 层，地址后面加 `?low=1` 也是 6 层），跟着地形起伏，用一张“草窝在哪”的图（`MD_PATCHES` 画出来、虚了边）挖掉没草的地方。每一片有多浓，按“视线在这一层里走了多远”算（视线贴得再平也只算到一定长度，不然远处的雾堆会变成地上一块实心的白）。雾贴地的浓一点，往上淡掉；草窝边上雾顶矮下去、也淡下去，所以侧着看是一个个软软的雾堆，没有硬边。雾堆的顶照噪声图鼓鼓囊囊、慢慢飘（噪声在前后方向上拉长了：上下两层斜着看取的是前后错开的地方，花样太碎会叠出一道道横纹，像水面）；雾堆上面被月光照着亮、底下暗一点；朝月亮那边的雾亮一点；人走过去，腿边搅开一点。透明的东西不写深度，雾和远处的布景板（树篱、远山）只能靠先后次序，所以雾按深度切成三段，和布景板一段隔一段地画。
- 草：只长在草窝里，一根根细长的叶子，叶面总朝着镜头（侧面看过去是一笔弯线），底下渐渐透明（多重采样的覆盖，`alphaToCoverage`，不用排先后），跟着阵风摆；人走过去，离人不到 0.7 米的往两边让、往下压（跳起来就不让了）。
- 为它改的几处：第 36 章的结尾画面上可以按 → 接着往前走（`69-h12-bell.js` 的 `cont`），门外的天也是白的（以前门外露出一块厂房里的黑天）；厂房里的光原来登记到 X + 62，和门外那一片白重在一处，出了门先暗下去一截才变白，现在登记到门口为止；从后面的章节往回走进铃那一章，结尾不再演一遍；整条路尽头的空气墙从第 36 章挪到第 37 章坡顶；章节菜单右边一列分成“工厂深处”“出了工厂”两组。两章之间的路在 `69-zz-links.js` 最后一段：门外十几米还是那一片白，中间几个关键帧把雾色和天边写成一样的灰（关键帧之间雾色是按线性光插的、天是按屏幕上的颜色插的，不写死的话，雾里远处的树会比天还亮，像一个个白影子）。
