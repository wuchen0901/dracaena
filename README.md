# The Last Light

一个横版解谜冒险的原型。代码全部在 `Last/` 里，用 three.js 写成，直接在浏览器里运行。

页面只有一份：`Last/escape.html`（2026-11-15 把原来单独的旧原型页面 `sidescroller.html` 并了进来），一共三十六章，排成一条路：

- 第 1–8 章：新故事《逃出工厂》的灰模（七章加结尾），见下面“《逃出工厂》故事灰模”。原来的第一章“焚化炉”2026-11-15 删掉了，游戏从“分拣”开始；2026-11-16 在“大门”和“结尾”中间加了一章“雾”（第 7 章），结尾成了第 8 章。
- 第 9–22 章：旧原型《铁锈与微光》的十四章，旧的第 k 章现在是第 k + 8 章（加“雾”以前是 k + 7，2026-11-16 以前的提交说明、设计文档里的章节号是那时候的）。其中旧第九章“山洞与暗河”（现第十七章）是 2026-11-13 新加的、要游泳的一段长山洞；旧第十章“吊绳与高台”（现第十八章）是同一天新加的、要跳起来抓住绳子往上爬的一段大台阶；旧第十一章“夜搜”（现第十九章）是 2026-11-14 新加的：夜里一架直升机用探照灯沿着公路找主角，要一处一处躲过去，等它飞走。故事还在重写，这三章先放在旧原型的结局后面。旧第十二、十三章（现第二十、二十一章）是《长夜》的原型 C（机房与选择），见下面“《长夜》原型 C”。旧第十四章“墙”（现第二十二章）是 2026-11-16 试画面风格的一关，见 `design/visual-style.md`。
- 第 23 章“高台”：2026-11-16 加在最后的一关推箱子的试验关，见下面“第 23 章 · 高台”。
- 第 24 章“水下实验室”：入口在水底，要潜下去开闸门、游进去，见下面“水下实验室（第 24 章）”。
- 第 25–36 章“工厂深处”：2026-11-16 加的十二个恐怖工厂的场景（冒泡的绿色药水、暗红的沉淀池、熔渣、漏液、冷库、停电的车间……），接在水下实验室后面，见下面“工厂深处（第 25–36 章）”。

三十六章从头到尾接成一条路（2026-11-16），从第 1 章开始一直往右走就能走到第 36 章，不用开章节菜单，中间不黑屏、不停下来：

- 世界里挨着的章节（第 1–8 章、第 9–16 章）照旧一直往右走就进了下一章。
- 不挨着的几处（在世界里隔着空气墙和几百米空地，各章的地面高度、室内室外也对不上）用一段“雾里的路”接起来：走到这一章的尽头，越往前雾越浓（夜里、屋里是越走越暗），浓到什么都看不见的那一步，人被挪到下一章的入口，接着走，雾又散开。人一直在走、一直听玩家的；往回走雾就退回去；到了下一章站着不动，雾过两三秒也散。第 17 章走出山洞、第 18 章在最高一级台阶上往矮墙那边走、第 19 章走进林子里的浓雾、第 20 章出了作坊的门（原来是黑一下）、第 22 章翻过第二道墙、第 23 章翻过高墙以后，都是这样接到下一章。
- 演结局的三章 —— 第 8 章“结尾”、第 16 章“生态中枢”、第 21 章“机房” —— 结局画面最底下一行多了“按 → 接着往前走 · 第几章 某某”：按一下 → / 回车 / 空格 / E（触屏点一下或往右划）同样起一阵雾，人出现在下一章的入口，接着往右走。一直按着没松的 → 不算（结局不会被带过去），结局画面刚出来的 1.5 秒里也不接受；按 R 照旧是再看一遍 / 回到最后的选择。
- 怎么登记：出口在章节文件里（`src/20-world.js` 的 `chapterExit(n, { a0, a1, when, tint })`：从 a0 起雾，到 a1 全是雾；when 是另外要满足的条件，比如得站在最高那一级上、门得开着；tint 是雾的颜色），入口是下一章章节对象上的 `enter: [b0, b1]`（人出现在 b0，走到 b1 雾散尽）。过程在 `src/80-ui.js` 的 `stepMist` / `walkInto`；雾一半是场景里的雾变浓（`36-lights-fx.js` 的 `applyEnv`），一半是盖在画面上的一层颜色（网页里的 `#mist`）。人还在雾里走的时候，下一章入口那一带的布景就提前搭（`38-stream.js` 的 `streamZones` 多了第二个位置），到了不卡。
- 走进下一章的时候先把走完的这一章记成“已经走完”：故事进度（救没救小猫、灯泡在不在包里……）照实际玩的留着，不会按“跳过去”重新补。走进来的人出现在入口、不在出生点，也不演“从这一章开始”的开场（比如工厂那一章从上层掉下来）。
- 工具页（`Last/tools/`）把游戏装在 iframe 里、一章一章单独摆主角截图：在那里走到一章的尽头不接下一章（`80-ui.js` 的 `LINK`），地址后面加 `?link=1` / `?link=0` 可以硬开、硬关。调试接口多了 `__g.walk(n)`：像从上一章一路走过来那样进第 n 章。
- 查过的：每一个接口都在无头 Chrome 里用自动玩家按住 → 走过一遍（挨着的 14 处、雾里的 6 处、三章结局的 5 种结局），又不重置地从第 16 章的结局连着走到第 24 章；几处雾里的画面截图看过。章节里面的谜题没有从头到尾连着玩一遍（接口前面是直接把人摆过去的），没有亲手玩，也没在手机上试。

- 第 21 章“墙”（`src/69-ch14-wall.js`，旧编号 14，`?ch=21`）：试画面的一关（近处做细、远处压暗，雾里的剪影），接在旧原型后面。先是一道齐胸高的矮砖墙；2026-11-16 在它右边加了一个小关卡 —— 第二道墙有两米高，从地上跳手够不着墙头，要按住 E 把左边那只旧木箱沿着地上的拖痕推到墙脚，跳上箱子，再朝墙跳。箱子的高度正好是两道墙的高差；这一段路是平的、直的（箱子只能在平地上推）。两道墙都是爬过去的（2026-11-17，以前是跳起来整个人从墙头上飘过去）：朝墙跳，手够得着墙头就扒住，用到处都有的那段攀爬动作把身子撑上去，站到墙顶上（墙顶上能走）；矮墙往前一走就跳下去了，高墙那一边有两米，走到边上会转过身来，扒着墙头倒着爬下去（攀爬动作倒着放，`50-player.js` 的 `mantle.rev`），吊直了再松手。

箱子、推车平时不挡路（2026-11-17）：人在地上走着碰到推得动的箱子、电池、线圈，《逃出工厂》路上的铁箱、装衣服的推车、院子里的三样货箱，就从它前面（离镜头近的那一侧）让一步走过去，不用再跳。朝它跳起来照旧能落到顶上、扒住边缘爬上去；按住 E 走过去照旧是抓住推。搁在台子、架子上的箱子（第 2 章装卸台上的、第 23 章站台上的、第 29 章铁架子上的）不绕，照旧挡人，免得人走到台子外面的半空里。怎么登记：方块上写 `thru: true`（推得动的东西默认就是），`zf` 是它前脸离路中间多远；判定在 `src/20-world.js` 的 `sideHit`、`50-player.js` 的 `stepPlayer`，画面上那一步在 `50-player.js` 的 `stepSidestep`（只是画面，玩法还在 z = 0 上）。查过的：自动玩家从两边走过二十来样东西都过得去，跳上去、按住 E 推都和以前一样；没有亲手玩，软件渲染的截图太暗，看不清人让出去那一步的样子。

下面各节说到旧原型的“第几章”、源码文件名里的数字（`69-ch11-heli.js` 之类），都还是旧的编号；说到《逃出工厂》的“第几章”、`escape/` 里的文件名（`62-e2-sorting.js` 之类），都还是故事文档里原来的编号（文档里的第二章“分拣”是游戏的第 1 章）。

## 运行

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory Last
```

然后在浏览器打开 <http://127.0.0.1:8765/escape.html>。页面需要联网，three.js 从 cdn.jsdelivr.net 加载。

画面最后统一过一遍后期（远处轻微模糊、统一调色、胶片颗粒，见 `design/visual-style.md` 第 8 条）：玩的时候按 G 开 / 关对比，地址后面加 `?post=0` 关掉。

没有装 Python 的机器（比如 Windows）用 `node Last/tools/serve.mjs 8765` 代替上面那一行，`.claude/launch.json` 里对应的是 `last-prototype-node`（端口 8771）。

地址后面加 `?ch=4` 可以直接从第四章开始，`?ch=7` 是新加的“雾”，`?ch=9` 是旧原型的开头（工厂），`?ch=17` 直接进山洞，`?ch=18` 直接到吊绳那一章，`?ch=19` 直接到直升机搜人的那一章，`?ch=20` 从凿记号开始玩《长夜》原型 C，`?ch=21` 直接进机房（灯泡已经在包里），`?ch=22` 是“墙”，`?ch=23` 是“高台”，`?ch=24` 是“水下实验室”，`?ch=25` 到 `?ch=36` 是“工厂深处”的十二章。按 Esc 选章节：左边一列是《逃出工厂》，中间一列是旧原型和两个试验关，右边一列是工厂深处。

## 《逃出工厂》故事灰模

新故事（`design/environmental-escape-story.md`）2026-11-15 做了一版灰模，原来是七章加结尾；同一天把第一章“焚化炉”删掉了；2026-11-16 在大门后面加了一章“雾”。现在七章加结尾，是游戏的第 1–8 章，直接打开页面就从“分拣”开始：

<http://127.0.0.1:8765/escape.html>

地址后面加 `?ch=4` 直接从第四章开始（1 到 7 是七章，8 是结尾）；按 Esc 也能选章节。存档是 `escape-factory-save-v3`，所有章节共用一份（加了“雾”以后后面的章节号都挪了一位，`v2` 对不上了；更早的 `escape-factory-save-v1` 和旧原型单独那份 `rust-glimmer-save-v1` 也不再读）。

- 第 7 章“雾”（`escape/68-e8-fog.js`，2026-11-16 加的）：出了林子，路往山上去，起了雾。看守打着手电从山下一个一个跟上来，在雾里往下照。规矩是**光照到身上时站住别动**（雾里只看得见动的东西）；在光里走、跑、跳就被盯上，盯满了回到存档点。路上要跳过一棵倒树、一道干砌石墙。半路上石头后面蹲着另一个逃出来的人：灯一扫到他，他跳起来就跑，几盏灯一齐落到他身上，他举手，被两个看守押下山去（第 6 章拉开过囚车的锁扣，他的衣服颜色和那时跑掉的人对得上）。画面照 `design/visual-style.md`（着色是从“夜搜”那一章抄过来、改成跟着一条前后弯的路）。两头邻章画在布景板上的远景在雾里是一块块发蓝的画，镜头在这一章里时把它们淡掉。`Last/tools/fog-route.html` 是这一章沿路的画面和自动玩家的检查（`?layout=route` / `check`）。

- 删掉焚化炉：那一章的源码 `escape/61-e1-furnace.js` 删了（git 历史里还在）。它搭的几样东西搬到了“分拣”（`62-e2-sorting.js`）：地形的起点、左边那道墙（原来留门洞通焚化炉，现在封死）、挡着往左走的墙、教“← → 移动”的提示。后面几章布景的随机数种子、人物的随机数都照删以前的接着算（`src/20-world.js` 的 `origN`、`62-e2-sorting.js` 开头的 `_figSeed`），位置、存档点、碰撞、每个人的长相都和删以前一样（对照提交过的页面查过）。开场“在推车上醒来”没有了，第六章（接收）“打倒扔上车”要让玩家想起开场的那一层现在没有铺垫。公共部分为它加的 `pose.lie`（仰面躺着）现在没有章节用。
- 灰模的意思：先看故事的顺序、每一章的规矩走不走得通。人物是一套简单的小人，场景是方块和剪影，造型都没定；每一章比文稿估的短，整个走一遍十几分钟。
- 多出来的两个按键：按住 `Shift` 慢走（游戏第 1 章跟推车、第 3 章跟队伍、第 4 章在检修道上都要用）；按 `C` 换主角自己衣服的颜色（蓝 / 砖红 / 土黄 / 绿，故事文档里这一条还没定，先放着对比）。
- 每一章做了什么、和文稿不一样的地方，记在故事文档的第十一节。
- 源码：公共的部分还是 `Last/sidescroller/src/`（核心、角色、玩家、声音、界面），这几章在 `Last/sidescroller/escape/`。`bash Last/sidescroller/build.sh` 把它们和旧原型的十四章拼成一份 `escape.html`。两段在世界里不重叠：旧原型还在原来的位置（从 x = -60 起），《逃出工厂》整段挪到它左边（`escape/60-kit.js` 的 `EX`，中间空出一千来米；删掉的焚化炉原来在 `EX - 60` 到 `EX + 80`，那一段空着）；旧原型的章节号写成 `OLD + 旧编号`（`src/20-world.js`，`OLD` 现在是 8）。挪位置、改编号时留意过的几件事：章节要按从左到右的顺序登记（地形、光的关键帧都按登记的先后接起来）；每章布景的随机种子按它原来的编号算（`origN`：旧原型是自己的编号，《逃出工厂》是删掉焚化炉以前的编号，后加的“雾”是 15），样子不变；光的关键帧会沿用上一个，旧原型的第一个从默认值算起（`env(…, true)`）；每次 `ceiling()` 是单独一段洞顶；照世界 x 算的花样（远山的山脊线）用 `ex(x)` 换回挪之前的 x；《逃出工厂》载入时用掉的关卡随机数，载完拨回去（`ESC_SEED`）。
- `escape/60-kit.js` 是这几章共用的东西：路上的人（每种身体零件一个实例化的网格，几十个人只多十来次绘制）、推车、铁栏杆、卡车、手电和探照灯“盯住人”的规矩、厂房的墙和布景。
- 为它在公共部分加的几处：`42-character-anim.js` 的 `pose.lie`（仰面躺着，开场用）；`40-character-build.js` 的 `HERO_TOP`（主角上衣在着色器里换色，只在第 1–8 章）；`52-audio.js` 的 `AUD.wheels`；`80-ui.js` 里章节可以自己写结局画面上的字（章节的 `end`）。旧原型的章节里这些都不起作用。
- 没做的：只在电脑上用自动玩家跑过，没有在手机上量帧数；声音只加了铃、炉口的火和几下闷响；旧的十三章没有拆。

## 第 23 章 · 高台

`Last/sidescroller/src/69-ch15-drop.js`，2026-11-16 加的推箱子试验关，接在“墙”后面（`?ch=23`，或者按 Esc 从右边一列进）。傍晚，一座废弃的货运站：

- 路被一堵 3.4 米的高墙挡住，从地上跳够不着墙头。唯一的一只箱子搁在路边 2.9 米高的旧站台上。
- 先跳上一垛枕木（1.45 米），再跳上站台头上的水泥墩（3.25 米），落到站台上；按住 E 把箱子往右推，推过站台的边，箱子绕着边角翻下去、砸在地上（扬起一团灰、镜头震一下，落地后还往前蹭一小段，给人留出站到它左边去推的空当）。
- 跳下去，把箱子推到墙脚，踩着箱子翻过墙头（墙头的铁丝网在这里被人剪开了）。墙那边是落下去的太阳。
- 高度是照 `50-player.js` 的跳跃算的：跳起来脚最高离地 1.22 米，扒得住的边比脚高不过 1.2 个身高。地面上够不着站台、水泥墩和墙头；水泥墩同时挡着，不让箱子从站台左边推下去。
- 箱子在站台上时是一个普通的 `pushable`，活动范围（`lo` / `hi`）跟着它在上面还是在地上变；翻下去、往下掉是这一章自己算的（掉下去的那一会儿箱子不挡人），落地以后又是普通的可推的箱子。按 R 回到存档点时箱子留在原处。
- 在无头 Chrome 里用自动玩家走通过（爬上去、推下来、推到墙脚、翻过墙），也试过从地上直接跳墙、跳站台和从站台边跑跳过去都过不去；没有亲手玩过，也没在手机上试。

## 《长夜》原型 C

> 2026-11-15：《长夜》方案已废弃，故事换成 `design/environmental-escape-story.md`（《逃出工厂》）。这一段原型的代码还在，留作参考；下面提到的 `long-night-story.md` 已删除，可在 git 历史里查看。

跳跃的手感（2026-11-16 改过，`src/50-player.js` 的 `stepPlayer`）：每一跳都一样高，点一下空格和按住不放没有区别（以前松开空格会把上升掐断，短按只有半人高）；腾空以后不按方向键，横着的速度原样留着，顺着起跳时的抛物线落下去（以前一松手就在半空刹住、直直掉下来），按着方向键还是能在空中带一点方向、往回收。最远能跳多远、最高能跳多高都没变。

跳跃的动作（2026-11-16 改过，`src/42-character-anim.js` 的 `JUMP`）：腾空不再是一个固定的姿势，按竖直速度从蹬地、提膝、最高点收腿、伸腿找地一路过渡到着地前；手臂像弹簧一样跟着，落地以后往下一荡再收回来。只改了动作，跳多高、多远、多久不变。`Last/tools/jump-sheet.html` 在游戏里把它拍成连续帧，`?layout=check` 报出高度、距离和手脚每帧挪了多少。

起跳前蹲一下蓄力（2026-11-16 加的，`src/50-player.js` 的 `JUMP_PREP`，动作在 `42-character-anim.js` 的 `JUMP.prep`）：按下跳以后人不是立刻离地，先屈膝往下一沉、上身前倾、手臂往后摆，站着 0.11 秒、跑着 0.06 秒以后才蹬起来（跑着跳比以前多冲出去 0.2 米才离地）。蹲的这一小会儿照样能走能跑；已经走出边缘才按跳的来不及蹲，直接跳；蹲的时候走出了边缘，到时候照样跳起来。离地以后跳多高、多远、多久都不变。

松开方向键（2026-11-16 改过，`src/50-player.js` 的 `STOP`）：在地上松手以后带着惯性刹一小段再停住 —— 跑着松手往前带不到半米、0.43 秒停住，走着松手带十几厘米（以前 0.07 秒就掉了六成多的速度，跑着也只带二十厘米，像被钉在地上）；刹车时重心压低一点、手臂放低。过场里主角自己走的那几段照旧，站的位置不变。`jump-sheet.html?rows=stop,wstop` 拍的是这一段。

按反方向掉头（2026-11-16 改过，`src/50-player.js` 的 `SKID`）：在地上跑着、走着的时候按另一边，先刹住再往回走，还冲得快的时候人朝着原来的方向刹车，慢下来才转过身 —— 跑着掉头往前多冲 0.3 米、0.27 秒刹住、0.53 秒往回跑到九成快（以前 0.08 秒速度就反过来了，人像被弹回去的）；走着掉头多冲 8 厘米。转身的动作（`42-character-anim.js` 的 `TURN.w`）也从“头一帧最快”改成起得慢、中间快、收得慢。腾空时的转向和过场里的走动照旧。`jump-sheet.html?rows=turn,wturn` 拍的是这一段。

起步（2026-11-16 改过，`src/50-player.js` 的 `START`）：在地上按下方向键，先匀着加速、快到全速了再缓下来 —— 0.2 秒到全速的一半、0.41 秒到九成，走和跑一样久（以前头一帧加速度最大，0.08 秒就到一半，人是窜出去的）；头 0.3 秒比以前少走 0.28 米。掉头以后往回跑也是这样起步，所以跑着掉头到往回九成快一共 0.68 秒。腾空时带方向、过场里的走动照旧。`jump-sheet.html?rows=go,wgo` 拍的是这一段。

攀爬的动作（2026-11-16 改过，`src/42-character-anim.js` 的 `MANTLE`，位置在 `src/50-player.js` 的攀爬那一段）：以前是摆好一个收着腿的姿势，整个人顺着侧面匀速滑上去、再平着滑到顶上 —— 跳早了、往下掉的时候腰撞在箱子角上（边缘只到腰那么高）最明显，人像被平着提上去的。现在是真的撑上去：两只手按在顶面上不动，刚抓住的那一下身子还往下沉一点（掉得越快沉得越多，最多 7 厘米），上身伏到顶面上，手臂把胯撑过边缘；一条腿先绕过边角踩到顶上、踩住就不动，身子从它上面翻过去，另一条腿顺着侧面垂着、最后才提上来迈到前面，一边站直。边缘高（吊着）的时候前面多一段往上拉，后面一样；从水里爬上岸、从绳子翻上高台用的也是这一段。什么时候能攀、花多久、最后站在哪都没变（腰高的箱角还是 0.62 秒）。对比图在 `generated_images/jump/mantle-01-before.png` / `mantle-01-after.png`（每格隔 1/30 秒）。在无头 Chrome 里拍过腰高、膝盖高、1.3 米高的边缘，朝左、搭出来的小孩、水里上岸各一次；从绳子翻上高台没拍，没有亲手玩过。

## 动捕对比（试验，2026-11-16）

想看看把主角的走和跑换成动作捕捉会是什么样：`Last/tools/mocap-compare.html`（通过本地服务器打开，比如 <http://127.0.0.1:8765/tools/mocap-compare.html>）左右并排放两个游戏，左边是现在程序化的走和跑，右边是同一个主角、地上走和跑换成 Mixamo 的动捕；两边按键、时间完全一样。能选跑、走、跑停跑、走跑交替、跑跳跑，能慢放到 1/10、暂停、单步。

- 游戏本身默认不变：地址后面加 `?mocap=1` 才打开（`src/42-mocap.js`，在 `42-character-anim.js` 摆完姿势以后混进去）。只管在地上走和跑；站着、起跳、腾空、落地、刹车、攀爬、游泳、推箱子、剧情动作的时候动捕淡出，照旧用程序化的。
- 动作取自 three.js 示例里的 `Xbot.glb`（walk / run，来自 Mixamo；Mixamo 官网要登录 Adobe 账号，这里的网络也连不上）。`Last/tools/mocap-extract.mjs` 只取需要的骨头和这两段，存成 `Last/models/mocap-xbot.json`（34 KB）。用到游戏里正式发布之前要再确认一下授权。
- 重定向：Xbot 和主角的骨架长短、绑定姿势不一样，先把主角每节骨头在绑定姿势里转到和 Xbot 同一个方向，以后每一帧 Xbot 那一节比绑定姿势多转多少，主角也多转多少；胯的上下颠按两个人胯的高度之比缩放。主角模型的三节脊椎是倒着编号的（Hips → Spine02 → Spine01 → Spine → neck，和 Mixamo 相反），对应表里换过来了。
- 步子按走过的距离推进，脚不打滑。Xbot 的 run 换算到主角身上原本约 2 米/秒，游戏里跑是 3.3 米/秒，所以右边的跑比原动作快 1.6 倍左右播放，步频偏急；走（1.25 米/秒）和原速差不多。没有脚的 IK，坡上脚会悬空或插进地里。
- 查过的：无头 Chromium 里拍过平地上跑、走、往左跑各一个循环，和程序化的并排比过；跑跳跑那一段看过动捕淡出、淡入没有跳变（落地后约 0.2 秒混回来）；对比页能载入、切换场景。没有亲手玩，没在手机上看，无头浏览器里页面跑得很慢（软件渲染），真机上的流畅度没看。

## 模型对比（试验，2026-11-16）

想分清楚画面不好到底是模型、动作还是美工的问题：把主角换成现成的、做得比较好的人物模型，和现在的主角放在同一个游戏、同一段路、同一套灯光和后期里比。

- `Last/tools/hero-compare.html`（通过本地服务器打开，比如 <http://127.0.0.1:8765/tools/hero-compare.html?model=michelle>）一屏四格：上一排现在的主角，下一排换来的模型；左一列程序化的动作，右一列地上走和跑换成 Mixamo 动捕。能换模型、去掉贴图（“平涂”）、换动作（站着 / 跑 / 走 / 跑停跑 / 跑跳跑）、慢放、换镜头远近。上下差得多是模型的问题，左右差得多是动作的问题，四格都不好看多半是画面本身（光、颜色、镜头、场景）。
- 地址后面加 `?hero=soldier`（或 `michelle`、`xbot`、`rpm`，或者任何一个 Mixamo 骨架的 `.glb` 地址，比如自己放在 `Last/models/` 里的 `?hero=models/xxx.glb`）才换；加 `?heroflat=1` 去掉贴图。代码在 `src/40-character-build.js` 的 `HERO_TEST` / `prepHeroTest`：骨头改成主角的名字（脊椎倒过来对），T 字站姿按主角的绑定姿势一节一节转过去，补上主角身上有的 `headfront`、`head_end` 两个点 —— 这样游戏里所有程序化的动作、`?mocap=1` 的动捕都直接能用在它身上。
- 模型是 three.js 官方示例里的（Soldier、Michelle、Xbot 来自 Mixamo，还有一个 Ready Player Me 的样例人物），运行时从 GitHub 上 three.js 的 r170 版本直接读，仓库里不放这些文件，要联网。都是成年人的比例，缩到了主角的身高。只拿来对比，正式用之前要看授权。
- Inside 的主角模型没有用：那是 Playdead 的商业资产，官方没有放出来，网上能找到的都是从游戏里扒出来的。
- 截图在 `generated_images/hero-compare/`（每张都是四格，跑起来的头几帧）。近看（`*-near.jpg`）上下两排差别很明显 —— 换来的模型有布料、头发、鞋的细节和贴图；但在游戏实际的镜头远近（`michelle-run-far.jpg`）下，主角只有一百来个像素高，上下两排几乎一样，画面里占主导的是场景和光。
- 查过的：无头 Chromium（软件渲染）里四个模型都能载入，骨头对上，跑、走、站着的画面看过，没有报错；跳、攀爬、游泳、推箱子、抓绳子这些动作没有在换来的模型上逐个看过，手的反向运动学按主角的手臂长度算，换来的模型上可能够不准。没有亲手玩，没在手机上看。

## 工厂深处（第 25–36 章）

2026-11-16 加的一组恐怖工厂的灰模，十二章，每章一个场景、一条规矩。接在第 24 章“水下实验室”后面：实验室恢复电源以后往里面走，起一阵雾，就进了第 25 章；以后每一章走到头都用“雾里的路”接下一章，第 36 章演完是这一组的结尾（结尾画面上按 R 再听一次铃）。设计说明见 `design/deep-factory.md`。

源码在 `Last/sidescroller/src/69-h00-kit.js`（共用）和 `69-h01-vat.js` … `69-h12-bell.js`。章节在世界里从 x = 3000 起，每章占 130 米（`hX(k)`），章节号是 `HN(k) = OLD + 17 + k`。共用的东西：

- `ooze()`：一池液体（绿色药水 / 暗红 / 熔渣 / 污泥 / 浑水）。液面是自己发光、慢慢翻动的着色器，靠镜头那一面切开，看得见里面往上冒的泡；隔一会儿液面上冒一个泡，偶尔一个大的；上面一层同色的低雾。掉进去回到存档点。液面高度可以是函数（第 29 章的液面往上涨）。
- `hWatch()`：拿手电扫的看守。`rule: 'move'` 照到身上时在动才算被看见，`'any'` 照到就算（要躲，或者 `hidden()` 说藏好了）。
- `hCut()` / `hCutFace()`：地面只铺到镜头前面一点，前面一道黑的切口，和液体的剖面一样，整章像一个剖开的模型。
