# Automatic saves and loading

Normal play no longer exposes scene-replay shortcuts. Esc / the top-left Pause control opens a menu with Continue and Load saves. The load menu lists named automatic saves from oldest on the left to newest on the right, with five entries per page and Japan-time timestamps. The caught-screen action opens that same list. R remains a shortcut to the newest record. Fresh installs start at reclamation; opening the game resumes a valid local save automatically.

Safe milestones proceed through reclamation (-3550), the factory manual cutoff (-2990), factory escape (-2600), station exit (-980), forest (-90), pre-canal (1190), far bank (1880), inner sentry approach (3080), sentry cleared (3280), the interior salvage line (4900), the prison wall, the exterior dog-and-kitten chase, outside police approach (7200), and police cleared (7690). The factory cutoff save stores the pushed box position and stopped-belt state. The dog-completion snapshot also stores the rescued kitten as a follower. The existing gate-open save also persists. Active hiding and caught states never replace the safe snapshot, so retry does not restore an exposed or frozen character. Each hiding encounter saves before danger; completing it saves the cleared milestone without teleporting the live player.

The versioned `the-last-light.autosaves.v1` archive stores one record per named progress slot plus the ID chosen for resume in one JSON write. Reaching a slot updates it; if play resumes from an older slot, the next reached slot replaces that branch and clears later slots. Each snapshot includes checkpoint, gate state, night amount, inner-sentry status, kitten-rescue status, outside-police status and alarm flag. Meaningful checkpoint/story changes create records; lighting interpolation alone does not flood history. `readProgress` validates the full snapshot. Legacy checkpoint-only saves remain readable; the controller migrates the old split night/escape keys once when the primary snapshot lacks story fields. Later loads use the unified snapshot only.

Load restores checkpoint position, resets velocity, jump buffers, input, camera and animation, restores scene flags, and closes failure/pause overlays. Pause stops movement, encounter timers and animation updates. If persistent storage fails, an in-memory safe snapshot remains loadable for the session and the existing storage-unavailable notice is shown.

Validation: 31 tests and Cocos TypeScript checking pass. Added tests cover full story-state round trips, safe patrol retries, non-regressing checkpoints, malformed data, old-save compatibility and the station exit checkpoint. Live Cocos preview confirmed removal of replay buttons, the pause menu, loading its latest save and refresh-to-resume. Mobile-device and audio-pause behavior were not verified; music/ambience currently continue during the pause menu.


History migration imports the previous single saved snapshot as one named record with an unknown timestamp. Older overwritten records cannot be reconstructed. Archive parsing validates records, collapses duplicate old entries into the latest snapshot for each slot, orders by story progress and skips corrupt entries. Selecting a record updates the resume ID without creating a duplicate record. Pagination exposes entries beyond the first page.

History validation: 35 tests and TypeScript checking pass, including names, repeated visits, sorting, imported unknown times, invalid records and loading an older entry without losing newer history. Live preview confirmed the migrated named save, chronological list, and click-to-load behavior.
